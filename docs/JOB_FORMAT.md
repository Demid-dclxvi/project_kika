# Файл задания на расчёт

Задание — файл JSON: какой материал, где деталь закреплена, какие нагрузки на неё действуют. Формат тот же, что у прототипа, поэтому задания из `prototype/examples` работают без изменений.

```
kika run деталь.gcode задание.json
kika run задание.json              G-code берётся из поля "gcode" (путь — от папки задания)
```

Или перетащите файл задания на `kika.exe`.

## Пример

```json
{
  "gcode": "bracket_side.gcode",
  "material": "PLA",
  "target_sf": 2.0,
  "fixtures": [
    {"name": "Саморезы", "where": [
      {"hole": {"axis": "x", "center": [12, 15], "radius": 2.5}},
      {"hole": {"axis": "x", "center": [28, 15], "radius": 2.5}}]},
    {"name": "Стена", "where": {"side": "xmin"}, "components": "x"}
  ],
  "cases": [
    {"name": "Лампа 2 кг", "duration": "long", "temperature": 30,
     "loads": [{"type": "mass", "where": {"hole": {"axis": "y", "center": [62, 15], "radius": 4}},
                "kg": 2, "direction": "-y"}]},
    {"name": "Удар", "loads": [{"type": "impact", "where": {"side": "xmax"}, "kg": 0.3, "height": 100,
                                 "direction": "-y"}]}
  ]
}
```

## Оси и координаты

Все направления — в осях принтера: **X, Y** — по столу, **Z** — вверх по слоям. Если деталь в работе стоит иначе, чем печаталась, направления задаются в осях печати: кронштейн, напечатанный на боку, нагружается весом лампы вдоль −Y, а не −Z.

Координаты — в миллиметрах от минимального угла габарита детали (`"coords": "part"`, по умолчанию). С `"coords": "printer"` — в координатах стола принтера, как в G-code. Габарит детали показывает `kika run` в строке «габарит».

## Поля задания

| Поле | Что это | По умолчанию |
| --- | --- | --- |
| `material` | название из базы (`kika materials`) или свой материал, см. ниже | по типу пластика из G-code, иначе PLA |
| `target_sf` | требуемый запас прочности: от него зависит итог «выдержит / мало запаса» | 2 |
| `fixtures` | закрепления, общие для всех случаев | — |
| `cases` | расчётные случаи (обязательно хотя бы один) | — |
| `coords` | `"part"` или `"printer"` | `"part"` |
| `gcode` | файл G-code, если он не указан в командной строке | — |
| `model` | вместо `gcode`: модель STL, 3MF или STEP — её нарежет свой слайсер (см. «Задание по модели») | — |
| `print` | настройки нарезки модели (см. «Задание по модели») | все по умолчанию |
| `voxel` | размер вокселя, мм (меньше — точнее и дольше) | подбирается по `max_elems` |
| `max_elems` | предел числа элементов сетки | 150 000 |
| `title`, `subtitle` | название и описание — для отчёта | — |

### Закрепление

| Поле | Что это |
| --- | --- |
| `where` | область на поверхности детали (см. «Области») |
| `components` | какие оси закреплены: `"xyz"` (по умолчанию), `"x"`, `"yz"`… Упор в стену — `"x"`, если стена перпендикулярна X |
| `name` | название для отчёта |

### Расчётный случай

| Поле | Что это | По умолчанию |
| --- | --- | --- |
| `name` | название | «Случай N» |
| `loads` | нагрузки (хотя бы одна) | — |
| `fixtures` | свои закрепления случая — заменяют общие | общие |
| `duration` | `"short"` — кратковременная, `"long"` — длительная (ползучесть: прочность и модуль снижаются), `"cyclic"` — циклическая (усталость) | `"short"` |
| `cycles` | число циклов для `"cyclic"` | 100 000 |
| `temperature` | температура детали, °C: снижает модуль и прочность, выше теплостойкости — предупреждение | 23 |
| `thermal_expansion` | `true` — добавить напряжения от нагрева зажатой детали (нужна `temperature`) | `false` |

## Задание по модели

Вместо готового G-code можно указать модель (STL, 3MF; STEP — в программе из папки с окном): `kika run` нарежет её своим слайсером и посчитает по получившемуся G-code. Пути — от папки задания.

```json
{
  "model": "bracket_L.3mf",
  "print": {"printer": "qidi_q2", "layer_height": 0.2, "walls": 3, "infill": 25, "pattern": "grid",
            "rotate": [90, 0, 0]},
  "material": "PETG",
  …
}
```

| Поле `print` | Что это | По умолчанию |
| --- | --- | --- |
| `printer` | `qidi_q2` (QIDI Q2, Klipper, стол 270 × 270 × 256 мм), `sparkx_i7` (Creality SPARKX i7, 260 × 260 × 255 мм, Marlin) или `generic_220` (220 × 220 × 250 мм, Marlin); с изменениями — `{"base": "qidi_q2", "z_hop": 0.2, …}` | `qidi_q2` |
| `filament` | пластик для температур, обдува и расхода в G-code: PLA, PETG, ABS, ASA, PC, PA, TPU, …-CF; с изменениями — `{"base": "PETG", "nozzle_temp": 245, …}` | тип пластика из `material` |
| `layer_height`, `first_layer_height` | высота слоя и первого слоя, мм | 0,2; первый — как остальные |
| `line_width` | ширина линии, мм | 0,42 |
| `walls` | число стенок (периметров) | 2 |
| `top_layers`, `bottom_layers` | сплошных слоёв сверху и снизу | 5 и 3 |
| `infill` | разреженное заполнение, % | 15 |
| `pattern` | рисунок заполнения (см. ниже) | `grid` |
| `infill_angle` | угол линий заполнения, градусы | 45 |
| `rotate` | поворот детали на столе: `[x, y, z]` в градусах, сначала вокруг X, потом Y, потом Z (любые углы — например, после «положить на грань» в окне) | без поворота |
| `scale` | масштаб по осям стола (после поворота): одно число или `[x, y, z]`, 0,01–100 | 1 |
| `position` | центр детали на столе `[x, y]`, мм; низ детали всегда на столе | центр стола |
| `skirt` | юбка вокруг первого слоя | `true` |
| `support` | поддержки: `none` — нет, `normal` — обычные, `tree` — древовидные | `none` |
| `support_angle` | нависание положе этого угла к горизонтали получает поддержку, градусы (5–85) | 40 |
| `support_on_bed_only` | поддержки только от стола, не стоящие на самой детали | `false` |

Кроме перечисленных, в `print` можно задать любую настройку печати (скорости `speed_*`, ускорения `accel_*`, `brim_width`, `seam`, `outer_wall_first`, `skirt_loops`, зазоры поддержек и другие), а в объектах `printer` и `filament` — любую настройку принтера и пластика. Полный список с пределами и значениями по умолчанию — `kika settings` (или `kika settings --json`; там же страница и раздел каждой настройки, как в окне). Неизвестный ключ или значение вне пределов — ошибка с объяснением.

Настройки, устроенные как в OrcaSlicer:

| Ключ | Что это | По умолчанию |
| --- | --- | --- |
| `first_layer_width`, `outer_wall_width`, `inner_wall_width`, `top_width`, `sparse_width`, `solid_width`, `support_width` | ширина линий по видам, мм; первый слой — для всех его линий | 0 — как `line_width` (первый слой — как остальные) |
| `top_thickness`, `bottom_thickness` | толщина верха и низа не меньше, мм: слоёв добавится, если `top_layers`/`bottom_layers` тоньше | 0 — только по числу слоёв |
| `top_pattern`, `bottom_pattern`, `solid_pattern` | рисунок верха, низа и сплошного заполнения внутри: `monotonic` (ряд за рядом, с соединениями у края), `monotonicline` (без соединений), `rectilinear` (зигзаг), `concentric` | `monotonicline`, `monotonic`, `rectilinear` |
| `ironing` | глажка верха: `none`, `top` (все верхние поверхности), `topmost` (только последний слой) | `none` |
| `ironing_flow`, `ironing_spacing`, `speed_ironing` | поток глажки (% от слоя той же площади), шаг, мм, скорость, мм/с | 10, 0,15, 30 |
| `xy_hole_comp`, `xy_contour_comp` | отверстия и наружный контур шире на столько, мм (минус — уже) | 0 |
| `elephant_foot` | первый слой уже на столько, мм | 0 |
| `bridge_flow`, `speed_bridge` | мосты (сплошное над пустотой): поток, %, и скорость, мм/с | 100, 50 |
| `small_perimeter_speed`, `small_perimeter_threshold` | мелкие периметры: % от скорости наружной стенки и радиус, мм | 50, 6,5 |
| `speed_first_layer_infill` | заполнение первого слоя, мм/с | 50 |
| `skirt_layers` | высота юбки, слоёв | 1 |
| `reduce_retraction` | без отката, если перемещение целиком над деталью | `true` |

Рисунки заполнения (`pattern`). Плотность у всех — доля объёма пластика в области заполнения: 20 % у гироида и у сетки — одинаковое количество пластика.

| Ключ | Рисунок | Какой он |
| --- | --- | --- |
| `grid` | сетка | две системы линий крест-накрест в каждом слое |
| `gyroid` | гироид | волнистые линии, от слоя к слою сдвигаются; одинаково прочен во всех направлениях |
| `cubic` | кубы | три системы линий под 60°, сдвигаются с высотой — складываются в кубы, стоящие на вершине |
| `honeycomb` | соты | шестиугольники, одинаковые на всех слоях |
| `3dhoneycomb` | 3D-соты | зигзаги, размах которых меняется с высотой — слои складываются в объёмные ячейки |
| `triangles` | треугольники | три системы линий под 60° в каждом слое |
| `tri-hexagon` | тригексагон | то же, но третья система сдвинута — звёзды из треугольников и шестиугольников |
| `rectilinear` | прямые через слой | одна система линий, через слой — поперёк |
| `line` | линии | одна система линий в одном направлении на всех слоях |
| `concentric` | концентрическое | петли, повторяющие контур |

Понимаются и названия OrcaSlicer: `zig-zag` и `alignedrectilinear` — `rectilinear`, `lines` — `line`, `trihexagon` — `tri-hexagon`, `honeycomb3d` — `3dhoneycomb`.

После поворота деталь ставится низом на стол в центр. **Оси и координаты закреплений и нагрузок — уже повёрнутой детали**, как она стоит на столе: так же, как в задании по G-code. Окно при повороте детали кнопками переносит выбранные поверхности и направления нагрузок само.

Командой `kika slice модель.stl` можно только нарезать модель и сохранить G-code (`--layer`, `--walls`, `--infill`, `--pattern`, `--support`, `--rotate x,y,z` и другие — `kika --help`); `kika run задание.json --gcode-out файл.gcode` вдобавок к расчёту сохраняет G-code нарезки.

`kika advise задание.json --goals economy,strength` подбирает для задания по модели положение детали и настройки печати — две цели из трёх: `speed` (скорость), `economy` (экономия пластика), `strength` (прочность). Нужный запас — `target_sf` задания: варианты с меньшим запасом не рекомендуются. `--save-job новое.json` пишет задание с лучшим вариантом: `print` — новые настройки и поворот, закрепления и нагрузки перенесены на деталь в новом положении (номерами граней, `max_elems` — сетки, на которой уточнялся запас). Просто вставить `print` варианта в старое задание можно, только если поворот не изменился: области `side`, `box`, `hole` задаются в осях детали на столе. Подробнее — [README](../README.md#подбор-положения-и-настроек-печати).

## Нагрузки

| `type` | Что задаётся | Поля |
| --- | --- | --- |
| `force` | сила, Н | `vector: [x, y, z]` или `value` + `direction`; `point: [x, y, z]` — сила приложена в стороне от поверхности (добавляется момент) |
| `mass` (`weight_kg`, `hanging`) | подвешенный груз, кг | `kg`, `direction` (по умолчанию `-z`), `point` |
| `bearing` (`bolt`, `pin`) | сила на отверстие от винта или оси: давит только на ту сторону, куда направлена | `vector` или `value` + `direction` |
| `pressure` | давление по нормали к поверхности, МПа | `value` |
| `moment` (`torque`) | крутящий момент, Н·мм | `axis` + `value` или `vector`; `center` — ось вращения (по умолчанию центр поверхности) |
| `impact` | удар падающим грузом | `kg`, `height` (мм), `direction`. Считается отдельным случаем, без других нагрузок |
| `displacement` (`enforced`) | заданное перемещение, мм; заодно считается нужное усилие | `vector: [x, y, z]`, `null` — ось свободна: `[null, -1, null]` |
| `gravity` (`acceleration`, `weight`, `self_weight`) | собственный вес или перегрузка, в g | `g: [x, y, z]` или число (вниз по Z); области не нужно |

У всех нагрузок, кроме `gravity`, есть `where` — область приложения.

**Направление** (`direction`, `axis`): `"+x"`, `"-x"`, `"+y"`, `"-y"`, `"+z"`, `"-z"`, `"normal_in"` (внутрь по средней нормали поверхности), `"normal_out"` (наружу) или вектор `[x, y, z]`.

## Области

Область — объект, строка (название стороны) или список областей (объединение).

| Описание | Что выбирается |
| --- | --- |
| `{"side": "xmin"}` | крайняя грань детали со стороны min X; также `xmax`, `ymin`, `ymax`, `zmin`, `zmax`. `"depth": 2` — захватить грани глубже на 2 мм; `"range": {"min": […], "max": […]}` — только внутри рамки |
| `{"box": {"min": [x, y, z], "max": [x, y, z]}}` | поверхность внутри рамки; `"normal": "+y"` — только грани, смотрящие в эту сторону |
| `{"hole": {"axis": "z", "center": [x, y], "radius": r}}` | стенки отверстия вдоль оси; центр — две координаты поперёк оси (или три). `"range": [от, до]` — по длине отверстия; `"outer": true` — наружная поверхность бобышки |
| `{"cylinder": …}` | то же, что `hole` |
| `{"sphere": {"center": [x, y, z], "radius": r}}` | поверхность внутри шара; `brush` — то же |
| `{"faces": [номера]}` | грани по номерам (так сохраняет задание приложение) |

Если область не задевает поверхность детали, расчёт останавливается с ошибкой и названием закрепления или нагрузки.

## Свой материал

Вместо названия — объект. С `base` берутся все свойства базового материала, заданные поля их заменяют:

```json
"material": {"base": "PETG", "name": "PETG моего принтера", "Zt": 18}
```

Без `base` нужно задать всё: `E1 E2 E3 G12 G13 G23 nu12 nu13 nu23` (модули, МПа, и коэффициенты Пуассона), `Xt Xc Yt Yc Zt Zc S12 S13 S23` (прочности на растяжение, сжатие и сдвиг, МПа), `density` (г/см³). Необязательные: `cte` (1/°C), `hdt`, `tg` (°C), `creep_strength`, `creep_modulus` (доли при длительной нагрузке), `fatigue_k` (показатель кривой усталости), `elongation` (удлинение при разрыве).

Оси материала: **1** — вдоль нити, **2** — поперёк нити в слое, **3** — по Z (между слоями).

## Что выдаёт расчёт

Для каждого случая — итог («ВЫДЕРЖИТ», «МАЛО ЗАПАСА», «РАЗРУШИТСЯ»), запас прочности и точка, где он наименьший, вид разрушения, наибольшее перемещение, предельная нагрузка («≈ 128 Н», «падение с ≈ 116 мм») и предупреждения. Запас считается вне мест закрепления и приложения нагрузок: там на воксельной сетке бывают ложные пики; если пик у опоры заметно ниже, об этом пишется отдельно.

Те же итоги и 3D-модель с раскраской по запасу, напряжениям, перемещениям и виду разрушения — в HTML-отчёте, который `kika run` сохраняет рядом с заданием (`-o` — в другое место).

`--json итоги.json` записывает итоги в JSON (поля как у прототипа: `sf`, `sf_xyz`, `mode`, `max_disp`, `reaction`, `applied`, `limit`, `warnings`…).
