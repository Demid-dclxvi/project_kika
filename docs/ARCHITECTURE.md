# Устройство ядра

## Принципы

- **Всё на C++20.** Ядро — библиотека без интерфейса `kika_core`. Консольная программа, тесты, будущее приложение на Qt и серверные расчёты работают с одним и тем же ядром.
- **Единицы:** мм, Н, МПа, мм³, °C. **Оси** — как у принтера: X, Y по столу, Z вверх по слоям.
- **Тензоры** — в нотации Фойгта `[11, 22, 33, 23, 13, 12]`, сдвиги инженерные (γ = 2ε), как в прототипе. Оси валика: 1 — вдоль нити, 2 — поперёк нити в слое, 3 — по Z.
- **Перенос со сверкой.** Каждый модуль прототипа переносится так, чтобы на тех же входах C++ и Python давали одинаковый результат. Отличия допускаются, только если они сознательные; все они перечислены ниже.
- **Своя линейная алгебра.** Плотные матрицы 6×6, разреженные CSR, многосеточный решатель и сопряжённые градиенты написаны в ядре (`kika::linalg`), без Eigen и AMGCL: нужных операций немного, алгоритм решателя совпадает с прототипом шаг в шаг (это упрощает сверку), а ядро собирается и проверяется без сторонних библиотек.
- **Потоки.** Сборка матрицы, умножения разреженных матриц и разложение грубой задачи идут на всех ядрах (`kika::set_thread_count`, переменная окружения `KIKA_THREADS`). Работа делится так, что результат до последнего бита не зависит от числа потоков.
- **Лицензии.** Только те, что допускают закрытую продажу: MIT, BSD, Apache, MPL, Boost, LGPL с динамической линковкой. AGPL — никогда. Реестр — в [THIRD_PARTY.md](../THIRD_PARTY.md).
- **Сообщения пользователю** — по-русски. Идентификаторы в коде — по-английски, комментарии — по-русски.

## Поток данных

```
G-code ──► gcode::parse ──► Toolpaths ──► воксели / сетка ──► поле материала
                                                                    │
отчёт ◄── запас прочности (Хоффман) ◄── напряжения ◄── МКЭ: K·u = f ◄┘
                                                          ▲
                                       нагрузки и закрепления
```

Позже на вход добавится модель (STL, 3MF, STEP), которую нарезает свой слайсер.

## Порядок переноса

1. Разбор G-code — готов.
2. Материалы и воксельная модель — готовы.
3. МКЭ и решатель — готовы: матрицы элементов, сетка, глобальная матрица и перемещения совпадают с прототипом.
4. Нагрузки и расчётные случаи, команда `kika run`. Проверка: консольная балка против аналитики, как в `prototype/tests/test_cantilever.py` (прогиб в пределах 3%, запас посередине пролёта — 1%); примеры кронштейнов дают тот же запас прочности, что и прототип.
5. Отчёт: тот же HTML с three.js, что у прототипа, — смотреть результаты в браузере.
6. Свой слайсер и тетраэдрическая сетка по модели.

## Отличия от прототипа

| Где | Прототип | C++ | Почему |
| --- | --- | --- | --- |
| Слова G-code без пробелов, `G1X10Y20E1` | `X10E1` читался как X = 10·10¹, экструзия терялась | X = 10, E = 1 | в числах G-code нет экспоненты |
| Строки с номером `N…` и контрольной суммой `*…` | строка пропускалась целиком | номер и сумма отбрасываются, команда выполняется | так G-code шлют по USB и пишут некоторые прошивки |
| Дуга с огромным радиусом | число точек не ограничено | не больше 100 000 точек на дугу | защита от испорченных файлов |
| Решатель для задач до 6000 неизвестных | прямой (SuperLU) | всегда многосеточный + сопряжённые градиенты; до 3000 неизвестных уровней нет, грубая задача решается Холецким за одну итерацию | один путь в коде, не нужен разреженный прямой решатель; ответ тот же с точностью невязки 10⁻⁷ |
| Начальный вектор оценки спектрального радиуса | `numpy.random.default_rng(0)` | свой генератор (splitmix64 + Бокс — Мюллер) | одинаков на всех платформах; влияет только на число итераций, не на ответ |
| Грубая матрица не раскладывается по Холецкому | псевдообратная матрица | сдвиг диагонали растёт 10⁻¹⁰ → 10⁻⁴ от наибольшего диагонального, затем сопряжённые градиенты | без разложения большой плотной матрицы по собственным числам |
| Грубая задача больше 4000 неизвестных | разреженный LU | сопряжённые градиенты с диагональным предобусловливанием до невязки 10⁻¹² | нет разреженного прямого решателя; бывает, только если огрубление застопорилось |
| Глобальная матрица жёсткости | точные нули из суммы элементов выбрасываются | портрет строится по соседству узлов, такие нули хранятся | на результат не влияет; сборка без сортировки, параллельно |
| Скалярные произведения и разложение Холецкого | одна сумма | четыре частичные суммы | быстрее; отличие — в последних знаках |

## Сверка с прототипом

`tools/compare_with_prototype.py` прогоняет примеры из `prototype/examples` и синтетические случаи из тестов прототипа через обе версии и сравнивает каждый отрезок (относительная точность 10⁻¹²) и все сведения о печати. В CI сверка идёт на Linux после тестов.

Материалы, воксели и МКЭ при переносе сверялись поэлементно на обоих кронштейнах при разных размерах вокселя: жёсткости, гистограммы направлений и плотности — до 10⁻⁹, матрицы элементов и глобальная матрица — до 10⁻¹⁵, перемещения — до 10⁻⁹. Эталонные числа из этих сверок вошли в тесты (`tests/material`, `tests/voxel`, `tests/fem`); в скрипт сверки они войдут вместе с командой `kika run`.

Скорость на кронштейне (110 тыс. элементов, 370 тыс. неизвестных), 2 ядра: сборка матрицы 0,8 с (прототип 4,5 с), подготовка решателя и решение 7,6 с (прототип 11,8 с, один поток). На машине с большим числом ядер быстрее; решение упирается в пропускную способность памяти.
