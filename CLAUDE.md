# Заметки для Claude

Проект: расчёт прочности деталей для FDM-печати по G-code; ядро переносится с прототипа на Python (`prototype/`) на C++20. Автор — Демид. Проектный документ (этапы, сроки, решения): https://claude.ai/code/artifact/f01a13ed-8ef5-4a14-8678-5e1580c6a166 — вкладка «Техническая часть» и вложенная «Вдвоём: прототип и MVP».

## Как работаем

- Общение, документы, сообщения коммитов и сообщения пользователю — по-русски. Идентификаторы — по-английски, комментарии — по-русски.
- `prototype/` — эталон, не изменять. Каждый перенесённый модуль сверяется с ним (`tools/compare_with_prototype.py`) и покрывается тестами в `tests/`.
- Сознательные отличия от прототипа записывать в `docs/ARCHITECTURE.md`, таблица «Отличия от прототипа». Состояние модулей — там же и в README.
- Новые зависимости — только через `vcpkg.json` и только с допустимой лицензией; сразу вносить в `THIRD_PARTY.md`. AGPL не использовать. Исключение — Qt для окна: готовые сборки Qt в DLL (LGPL-3.0, только динамически), не vcpkg; новые модули Qt — только под LGPL. OpenCascade (LGPL-2.1) — через vcpkg, но только DLL (триплет в `cmake/triplets`) и только в сборке с окном.
- Единицы мм, Н, МПа; нотация Фойгта `[11, 22, 33, 23, 13, 12]`, инженерные сдвиги.

## Сборка и проверка

- Пресеты: `win-debug`, `win-release`, `linux-debug`, `linux-release`; окно на Windows — `win-gui-debug`, `win-gui-release` (Qt из `QT_ROOT_DIR`, среда выполнения /MD, триплет `x64-windows-static-md` из `cmake/triplets`, STEP через OpenCascade — `KIKA_WITH_OCCT`, без тестов; в CI `ci-windows-gui` — с тестами); в CI — `ci-windows`, `ci-windows-gui`, `ci-linux` (с окном; предупреждения = ошибки).
- `cmake --preset linux-release && cmake --build --preset linux-release && ctest --preset linux-release`.
- Ядро — без сторонних библиотек (JSON свой, `kika::json`). Отчёт (`src/report`) использует zlib; через vcpkg подключаются zlib и Catch2 (тесты). Новые зависимости в ядро — только если своё писать неразумно.
- Файлы просмотрщика отчёта (`src/report/web`) встраиваются в программу скриптом `cmake/EmbedFiles.cmake`. Отчёт проверять в браузере: Chromium есть в среде (Playwright для Node — `NODE_PATH=/opt/npm-tools/node_modules`), WebGL — через `--use-angle=swiftshader --enable-unsafe-swiftshader`.
- В облачной среде Claude скачивание исходников библиотек с github.com/codeload закрыто сетевой политикой, поэтому vcpkg там не собирает Catch2. Ядро, `src/report` и `apps/cli` проверять прямой сборкой g++ и clang++ (`-std=c++20 -Wall -Wextra -Wpedantic -Wshadow -Werror`, нужны `-pthread` и системная zlib `-lz`), полную сборку с тестами — через GitHub Actions (`gh run watch`; логи CI оттуда не скачиваются, видны только статусы шагов).
- Clipper2 (слайсер) для прямой сборки в облачной среде: исходники 2.0.1 есть в sdist `pyclipr==0.1.8` с PyPI (`pip download --no-binary :all: pyclipr==0.1.8`, папка `external/clipper2/CPP/Clipper2Lib`) — компилировать `clipper.engine.cpp`, `clipper.offset.cpp`, `clipper.rectclip.cpp` и подключать `-isystem …/include`.
- Прямая сборка не видит ошибок в CMakeLists (забытая библиотека у цели), поэтому перед отправкой собирать и через CMake + Ninja: Qt — из распакованных пакетов (`CMAKE_PREFIX_PATH`), Clipper2 — своей заглушкой пакета (`Clipper2Config.cmake` с imported target `Clipper2::Clipper2` на собранную статическую библиотеку).
- STEP (OpenCascade) в облачной среде: пакеты Ubuntu `libocct-*-7.6t64`/`-dev` (+ `libtbb12`, `libtbbmalloc2`) скачать с archive.ubuntu.com и распаковать `dpkg -x` в свою папку; в `libocct-foundation-dev` нет заголовка `NCollection_AliasedArray.hxx` (ошибка пакета) — взять его из исходников OCCT тега `V7_6_3` (git с `--filter=blob:none` и sparse-checkout работает). Для OpenCascade 8.0.1 (как в vcpkg) — так же достать только заголовки тега `V8_0_1` и проверять `step.cpp` через `-fsyntax-only`. В Windows CI тесты идут и в сборке с окном — там чтение STEP проверяется на OpenCascade 8.
- Модели для проверок (STL, 3MF) удобно строить trimesh + manifold3d в своём venv; пример — `examples/bracket_L.3mf`. Окно с моделью без человека: `kika-gui examples/bracket_L.job.json --rotate x --run --field sf --screenshot окно.png`.
- Рисунки заполнения и поддержки в слайсере — свои алгоритмы (код Orca/Prusa/Cura не переводить: AGPL). Подбор печати (`src/advisor`, `kika advise`) режет и считает десятки вариантов — в тестах только грубые сетки (8000–20000 элементов), иначе тесты идут минутами.
- Принтер Демида — QIDI Q2 (Klipper + Moonraker, порт 7125, в локальной сети без ключа; Q2 не «заблокированный» Makerbase). Профиль `qidi_q2` — по умолчанию; стартовый код свой: `PRINT_START BED= HOTEND= CHAMBER=` (EXTRUDER по умолчанию 0 — ячейка QIDI Box), макросы прошивки — в репозитории QIDITECH/QIDI_Q2 (`config/gcode_macro.cfg`). Код и профили QIDI Studio/Orca не копировать (AGPL), только факты (параметры макросов, размеры).
- Сеть (`src/printer`) проверять без принтера: `python tools/mock_moonraker.py --port 7130` (имитация: печать по времени, пауза, отмена), затем `kika printer 127.0.0.1:7130`, `kika slice … --send 127.0.0.1:7130 --start`, окно — `kika-gui … --printer 127.0.0.1:7130 --send-print --printer-shot принтер.png`. Настоящий Moonraker (без Klipper) поднимается из его исходников в своём venv (`pip install -r scripts/moonraker-requirements.txt`) — так проверено, что он принимает файл и читает из G-code время, пластик, высоту и миниатюры. Локальным запросам к 127.0.0.1 мешает прокси — `NO_PROXY='*'`.
- Свои профили окна и `kika` лежат в папке настроек (`app::config_dir()`); для проверок — `KIKA_CONFIG_DIR` на свою папку.
- Сверка с прототипом: `python tools/compare_with_prototype.py --kika <путь к kika>` (нужны numpy и scipy).
- Демид собирает на Windows в Visual Studio; готовые программы берёт из артефактов CI: `kika-gui-windows-x64` (папка с окном, Qt, примерами) и `kika-windows-x64` (один `kika.exe`).
- Окно (`apps/gui`, Qt 6 Widgets, без moc): логику без Qt держать в `src/app` и покрывать тестами. Код должен собираться с заголовками Qt 6.4 (Ubuntu в CI) и 6.8 (Windows). Проверка без человека: `kika-gui --example --run --field sf --screenshot окно.png` (ещё `--section z:0.5`, `--deform`, `--tool hole --pick 0.5,0.5`, `--report`, `--save-job`, `--settings-shot`; для модели — `--rotate x`, `--support tree`, `--advise economy,strength --apply`; принтер — `--printer АДРЕС --send|--send-print --printer-shot`); код выхода 1 — были ошибки. `QWidget::grab` не видит рисования `QPainter` поверх OpenGL, поэтому снимок дорисовывается из `grabFramebuffer` (уже сделано в сценарии).
- Окно (`apps/gui`): вкладки «Подготовка», «Предпросмотр», «Расчёт нагрузок», «Принтер», слева — панель настроек печати (`settings_panel.cpp`). Логика без Qt: предпросмотр G-code — `src/app` (`preview.hpp`). Снимки вкладок: `--tab prepare|preview|strength|printer`, `--view part`, `--lay X,Y` (положить на грань), `--scale`, `--move X,Y`, `--set ключ=значение`, `--color speed`, `--layers 1:120`. Веб-интерфейс принтера — Qt WebEngine (`KIKA_WITH_WEBENGINE`, по умолчанию, если найден); в CI на Linux — `qt6-webengine-dev` и `QTWEBENGINE_DISABLE_SANDBOX=1`, на Windows — модули aqt `qtwebengine qtwebchannel qtpositioning`.
- Окно в облачной среде Claude: Qt не установлен, а системные пакеты без спроса не ставим. Заголовки Qt 6.4 — из пакетов Ubuntu (`apt-get download qt6-base-dev qt6-base-dev-tools libgl-dev libglx-dev libopengl-dev libegl-dev mesa-common-dev`, распаковать `dpkg -x` в свою папку), библиотеки Qt — из колеса PySide6 (`pip download`, распаковать). Компилировать с `-isystem` к заголовкам и `-fPIC`, линковать `libQt6*.so.6` из колеса с `-Wl,-rpath`; запускать под `Xvfb` с `QT_PLUGIN_PATH` на плагины из колеса и `LC_ALL=C.UTF-8`. WebEngine: заголовки — deb `qt6-webengine-dev` (6.4), библиотеки — колёса `pyside6_webengine` и `pyside6_addons` той же версии, что `pyside6_essentials` (распаковать в одну папку `PySide6/Qt`, у `libexec/QtWebEngineProcess` выставить права на запуск); запуск — `QTWEBENGINE_DISABLE_SANDBOX=1`, `QTWEBENGINE_CHROMIUM_FLAGS=--disable-gpu`, `QTWEBENGINEPROCESS_PATH`, `QTWEBENGINE_RESOURCES_PATH`, `QTWEBENGINE_LOCALES_PATH` на папки из колеса. Имитация Moonraker отдаёт на `/` простую страницу вместо Fluidd.
